# Finance Data Foundation

One governed finance data model — synthetic ERP extracts staged, converted,
deduplicated and reconciled with dbt on DuckDB, every metric defined once,
every tie tested on every build — and, as the foil, the naive consolidation
of the same files kept as a model so its cost stays measured: €24.5m of
phantom FY2025 revenue from złoty read as euros plus one extract loaded twice.

## The shape of the argument

Three entities export their ledgers the way ERP jobs actually do, each in its
own dialect:

| Entity | Quirk | What happens if you ignore it |
|---|---|---|
| DE01 Hamburg | `DD.MM.YYYY` dates, decimal commas | your query crashes — so this always gets fixed |
| DE01 Hamburg | the March 2025 extract job ran twice | parses cleanly; March counts double, silently |
| PL01 Kraków | posts in PLN, pads account codes | parses cleanly; złoty read as euros, silently |

The errors that crash are the cheap ones. The staging layer repairs all of
them once, in one place, and the test suite proves the repairs happened.

## Layout

```
generate_data.py        seeded synthetic ERP extracts -> data/raw/*.csv
tests/                  pytest invariants on the raw files themselves
models/staging/         dialect normalisation, FX, dedupe -> one governed GL
models/intermediate/    monthly balances and flows per entity + GROUP
models/marts/           fct_pnl_monthly, fct_working_capital_monthly,
                        fct_dso_definitions, fct_naive_consolidation
tests_dbt/              six reconciliations (journals balance, subledgers
                        tie to control accounts, inventory snapshot ties,
                        revenue ties to invoicing, no duplicate lines)
export_dashboard.py     bakes the built marts into dashboard.html
dashboard_template.html the page, minus the data
dashboard.html          the published, self-contained result
```

## Running it

```sh
pip install -r requirements.txt
sh run.sh
```

`run.sh` regenerates the extracts, runs the pytest invariants, runs
`dbt build` (9 models, 45 tests — a red build stops the pipeline), and bakes
`dashboard.html` from the marts. Everything is seeded; two runs produce the
same books to the cent.

## Provenance

The ledger is synthetic and generated by this project (seed 7) — no client
data anywhere. Every journal balances by construction, and the AR/AP
subledgers mirror their control accounts line for line, which is what makes
the reconciliation tests meaningful: they assert ties that genuinely hold,
and genuinely fail when a model is wrong.

The dashboard is vendored into the portfolio site at
[morichtereur.github.io](https://morichtereur.github.io/); this directory is
laid out to move into its own repository unchanged, at which point the site's
`sync:dashboards` script picks `dashboard.html` up from there.
